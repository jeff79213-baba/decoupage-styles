# 電腦桌面英文翻譯小工具 — 設計文件

日期：2026-08-28

## 1. 目標

製作一個 Windows 桌面翻譯小工具：當使用者在**任何應用程式**中反白一段文字後，滑鼠游標附近會浮現一個小翻譯圖示；滑鼠移到圖示上會彈出**臨時小卡**，顯示原文、翻譯、音標（若為單字），並有喇叭按鈕可朗讀發音。滑鼠離開或點其他處小卡自動消失。

## 2. 核心功能

1. **跨程式反白偵測**：使用 Windows 底層低階滑鼠鉤子（`pynput`）監聽滑鼠動作。於滑鼠放開（selection 結束）時，判斷是否發生反白。
2. **取得反白文字**：模擬送出 `Ctrl+C` 複製，再用 `pyperclip` 讀取剪貼簿內容；讀取後**還原使用者原本的剪貼簿內容**。
3. **翻譯**：呼叫 Google 翻譯免費介面（`translate.googleapis.com/translate_a/single`），支援單字與整句，目標語言為繁體中文。
4. **音標**：當反白內容為單字時，Google 介面會回傳 `src_pronunciation`（音標）並顯示；整句不顯示音標。
5. **發音朗讀**：小卡上的喇叭按鈕，使用 `pyttsx3`（離線 Windows SAPI 語音）朗讀原文。
6. **浮動小圖示**：取得反白文字後，在滑鼠位置旁建立一個小型無邊框圖示視窗（`tkinter`）。
7. **臨時小卡**：滑鼠移入圖示時彈出翻譯視窗；滑鼠離開圖示/小卡，或點擊其他位置，則小卡消失。
8. **常駐**：程式在系統工作列（tray）常駐，可隨時關閉結束。

## 3. 技術架構

| 元件 | 工具 | 說明 |
|------|------|------|
| 全局滑鼠鉤子 | `pynput.mouse.Listener` | 監聽按下/放開/移動，判斷反白動作 |
| 剪貼簿 | `pyperclip` | 讀取複製文字，還原原內容 |
| 翻譯 + 音標 | `requests` | Google 免費翻譯介面 |
| 發音 | `pyttsx3` | 離線 Windows TTS 語音 |
| UI（圖示/小卡） | `tkinter` | 無邊框浮動視窗 |

### 翻譯介面

```
GET https://translate.googleapis.com/translate_a/single?client=gtx&sl=auto&tl=zh-TW&dt=t&dt=rm&q=<原文>
```

- `sl=auto` 自動偵測來源語言；`tl=zh-TW` 目標繁體中文。
- `dt=t` 取得翻譯文字；`dt=rm` 取得音標（單字才會有）。
- 需對 URL 進行 URL-encode。

### 反白判斷邏輯（防誤觸）

- 按下（左鍵）→ 記錄按下位置與時間，並**記錄此動作前的剪貼簿內容**。
- 拖曳後放開 → 若按下到放開的位移大於門檻（例如 8px），視為一次反白選取。
- 放開當下模擬 `Ctrl+C` → 延遲約 100ms → 讀剪貼簿。
- 從新剪貼簿文字判斷是否與拖曳前相同：
  - 相同 → 可能是誤觸複製或無選取，**不彈圖示**。
  - 不同 → 以新文字當作反白內容，顯示圖示；**還原原剪貼簿**。

### 防抖

- 取得文字後，若連續多次觸發（例如快速操作），以最後一次內容更新小卡，避免閃爍。
- 翻譯請求使用非阻塞（背景執行緒），避免 UI 卡頓。

### 小卡消失規則

- 滑鼠離開「圖示 + 小卡」區域達一段時間（如 0.8 秒）→ 消失。
- 使用者左鍵點擊小卡區域以外的位置 → 消失。
- 小卡顯示後若完全不需要，移開游標即可。

## 5. 資料流

```
滑鼠按下(記錄原剪貼簿) → 滑鼠放開(位移>門檻) → 模擬 Ctrl+C
 → 讀剪貼簿 → 文字改變? → 是：還原剪貼簿 → 顯示圖示
 → 圖示 hover → 背景執行緒翻譯(原文/音標/翻譯)
 → 小卡顯示 → 滑鼠離開/點外部 → 小卡消失
```

## 6. 錯誤處理

- **無網際網路**：小卡顯示「無法連網，翻譯失敗」提示，不崩潰。
- **沒抓到剪貼簿**：不彈出圖示。
- **TTS 失敗**：喇叭按鈕無聲音，不顯示錯誤。
- **程式意外結束**：還原被改寫的剪貼簿。

## 7. 測試

- 單元測試：翻譯 URL 編碼、翻譯解析、音標解析、反白判斷門檻邏輯。
- 手動測試：在 Chrome、Word、記事本反白測試；確認小卡出現/消失時機正確；確認剪貼簿被還原。
- 此為**桌面 GUI + 全域滑鼠鉤子**，不涉及跨角色權限/金流/敏感資料，不需 E2E。以單元 + 手動驗證為主。

## 8. 部署

- 本專案為本機桌面工具，無 Firebase/GitHub Pages 需求。
- 仍會 commit + push 至 GitHub repo（依使用者慣例），但不做 hosting 部署。
