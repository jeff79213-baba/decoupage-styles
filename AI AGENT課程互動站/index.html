第 0 章

認識 AI Agent

AI 是你的員工：AI 是聰明但需要你交代的員工，Agent 是會自己動手做完的員工。

💡 核心概念

AI 是什麼？

AI 是「會回答問題的聰明機器」。就像一個很聰明但需要你交代的員工——你問它，它回答。

AI Agent 是什麼？

Agent 是「會自己動手把事做完」的員工。你交代一句話，它會自己規劃、動手、檢查、交差。

🏢 員工對比

比較AI（一般）AI Agent
你問它回答你回答你，還動手做
需要你每一步都要交代交代一句，自己完成
舉例「蘋果是什麼？」「幫我做一個自我介紹網頁」

✏️ 小測驗

1AI 和 AI Agent 最大的差別是什麼？

AI Agent 除了回答，還會自己動手把整件事做完。

2把 AI Agent 想成員工，什麼行為最像？

Agent 會自己規劃步驟、動手做、檢查結果，就像能幹的員工。

3「幫我做一個自我介紹網頁」這種指令，交給誰最適合？

這是一個「要動手做」的需求，正是 Agent 的強項。

📌 本節重點

AI Agent 是會幫你「動手做事」的工具，不是只會回答問題。接下來的課程，你要學的就是怎麼當一個好老闆，把工作交代給它。

第 1 章

安裝 Node 與 Git

先打好地基，才能蓋 AI 大樓。裝好 Node.js、npm 與 Git，後面的 AI 課程才走得下去。

🏭 為什麼先裝 Node

Node.js：電腦裡的小型工廠

讓 AI 工具跑起來的底層引擎。就像一座小型工廠，所有 AI 程式都要站在它上面才開得了機。

npm：應用程式商店

跟著 Node.js 一起裝好的「應用程式商店」，負責下載、安裝 AI 工具，跟手機裝 App 一樣。裝完 Node，商店也自動開張了。

🖥️ 模擬：安裝 Node.js

⏳ Git 的價值

Git：時光機 + 檔案保險箱

每次改動都存一個備份點（Commit），做壞了可以回到過去任何一次的狀態，改壞的檔案回不去？不存在的。

用蓋房子來比喻：先打地基（Node.js），再架鋼骨（Git），後面才有能力裝上 AI Agent 跟各種輔助工具。

✏️ 小測驗

1Node.js 在整個系統裡的角色？

Node.js 是「電腦裡的小型工廠」，所有 AI 工具都要站在它上面才跑得起來，沒有它任何 AI 程式都開不了機。

2npm 像什麼？

npm 跟著 Node.js 一起裝好，負責下載、安裝 AI 工具，就像手機的應用程式商店。

3Git 的「時光機」比喻是指？

Git 每次改動都存一個備份點（Commit），做壞了可以倒回任何一次的狀態，就像坐上時光機回到過去。

📌 本節重點

Node 是 AI 的地基，裝完它「應用程式商店」npm 也跟著有了；Git 是保險箱 + 時光機，改壞了可以倒回。驗證三連招 node --version、npm --version、git --version，看到版本號就是成功。

第 2 章

安裝 opencode

主角登場：僱用你的第一個 AI 員工。安裝 = 把員工帶進公司，設定 API 金鑰 = 給員工發薪帳戶。

🏢 僱用員工的第一天

安裝 = 把員工帶進公司

輸入 npm install -g opencode-ai，把 opencode 裝進電腦，就像跟員工喊一聲「今天開始你來上班」，員工就正式入職了。

設定 = 給員工發薪帳戶

執行 opencode auth login，貼上你的 API 金鑰。opencode 的「大腦」在雲端，沒有這張識別證，AI 助理只會發呆。

⏸ 授權點

API 金鑰必須由你親手提供——AI 不能幫你申請、也不可以亂猜。

🖥️ 模擬：安裝並啟動

🔑 API 金鑰 ⏸ 授權點

這一步，AI 不能代替你

API 金鑰是你的私密資料，AI 不能幫你申請、也不可以亂猜。必須由你本人到提供者網站（例如 OpenRouter、NVIDIA）申請一組金鑰，再親手貼給 opencode。

✏️ 小測驗

1安裝 opencode 的指令是？

用「應用程式商店」npm 安裝名為 opencode-ai 的全域工具，裝好後在任何資料夾都能呼叫它。

2API key 應該怎麼處理？

API 金鑰是你的私密資料，必須由你本人申請後親手貼給 opencode，AI 不能代辦。

3opencode 是整個系統的什麼角色？

opencode 就是「AI 助理本體」，你打字它做事，是整個課程的主角與靈魂。

📌 本節重點

opencode 是「AI 助理本體」，是整個系統的主角——Node.js、npm 都是為了讓它跑起來，其他工具也都是為了讓它更強才存在的。裝好它、貼上你自己的 API 金鑰，你就有第一個會動手做事的 AI 員工了。

🎬 劇本對話模擬

💬 為什麼要一步一步確認

brainstorming = 開會確認需求

AI 是你的員工，你請它做專案就像請員工接大案子。專業員工不會一拿到案子就悶頭亂做，而是先開會反覆問你「要做給誰？要什麼功能？長什麼樣子？」，確保雙方想的是同一件事。

好的專案 = 清楚的需求 + 一步一步的確認

講得越清楚，AI 越不容易猜錯。AI 拿設計文件、計劃給你看時，花 10 秒讀一下，回一句「OK」或「這裡要改」——你越認真確認，後面越不會做錯方向白費工。

🧠 陷阱提醒

⚠️ 沒講清楚需求就喊「全自動」

只丟一句「幫我做一個點餐網站」就希望 AI 一次做對？這就像去餐廳只說「隨便」，廚師只能亂猜，端出來的往往不是你要的。需求不清楚沒關係，AI 會反問你，照實回答就好。

⚠️ 跳過確認一路喊「快點做」

AI 把文件拿給你看時，不理它或直接說「好好好快做」，就像開會時老闆不表示意見，最後交出來的東西跟你想的完全不一樣。

✏️ 小測驗

1專案一開始，AI 反問你問題的階段叫什麼？

brainstorming 就是「開會確認需求」：AI 先反問你細節，確保雙方想的是同一件事，才不會做錯方向。

2為什麼要讓 AI 寫設計文件和計劃？

設計文件和計劃就像員工的企劃書、時程表，白紙黑字讓你先確認再施工，確認過後才不會白做工。

3正確的專案流程順序是？

完整 SOP：提出專案 → brainstorming 提問 → 寫設計報告 → 寫實作計劃 → 執行 → 測試 → 上傳部署。

📌 本節重點

好的專案 = 清楚的需求 + 一步一步的確認。跟 AI 合作的完整 SOP 是：提出需求 → 反問釐清 → 寫設計文件 → 寫實作計劃 → 動手做＋測試 → 上傳部署。AI 不會不問就亂做，也不會做完就交差——你只要把需求講清楚、每步認真確認，它就是你最可靠的員工。

第 4 章

第一次合作

讓 AI 幫你做出第一個看得見的作品——跟 AI 第一次合作，做一個自我介紹網頁，在你自己電腦上親眼看到它。

🏠 本機 vs 網路

先在自己家裡的客廳排練，不讓外人看到

這章做出來的網頁，只會在你自己的電腦裡跑、只有你看得到，還沒有「上網」、別人看不到、也不會有網址可以分享。這叫「本機預覽」——就像歌手開演唱會前先在自家客廳練一遍，練得好不好，只有自己知道，不怕出糗。

比較🏠 本機（自家客廳排練）🌐 網路上（公開演出）
在哪看自己的電腦，網址是 http://localhost:3000任何人的手機或電腦，網址像 https://你的專案.web.app
誰看得到只有你自己大家都看得到，可以分享網址
要部署嗎不用，做完就能看要（第 7 章教你上傳部署）

✏️ 小測驗

1「本機預覽」是什麼意思？

「本機預覽」就像在自家客廳排練——成品只跑在你自己的電腦裡（網址是 localhost），別人看不到，也不用怕出糗。

2本機跟網路上的差別是？

本機＝自家客廳（只有你），網路上＝公開演出（大家都看得到）。判斷方式看網址：localhost 是本機，web.app 是網路上。

3改壞了怎麼救？

Git 就像「時光機」，每次改動都存一個備份點（Commit），改壞了可以回到之前的版本。所以要記得「留備份」，改壞了不可怕，可怕的是改壞了回不來。

📌 本節重點

第一次合作，就是照流程走：提出需求 → AI 反問 → 確認設計 → AI 寫 code → 本機預覽 → 調整。「本機」＝只有你的電腦看得到（網址是 localhost），就像在自家客廳排練；「網路上」＝大家都看得到，要等第 7 章教上傳部署。改壞了別怕，Git 這台時光機可以救你回來。AI 能幫你做出「看得見」的東西——這就是它的威力。
