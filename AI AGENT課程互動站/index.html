第 0 章

認識 AI Agent

AI 是你的員工：AI 是聰明但需要你交代的員工，Agent 是會自己動手做完的員工。

💡 核心概念

AI 是什麼？

AI 是「會回答問題的聰明機器」。就像一個很聰明但需要你交代的員工——你問它，它回答。

AI Agent 是什麼？

Agent 是「會自己動手把事做完」的員工。你交代一句話，它會自己規劃、動手、檢查、交差。

🏢 員工對比

比較AI（一般）AI Agent
你問它回答你回答你，還動手做
需要你每一步都要交代交代一句，自己完成
舉例「蘋果是什麼？」「幫我做一個自我介紹網頁」

🍳 生活比喻：兩種員工

早餐店阿姨 ＝ 一般 AI

你說：「火腿蛋吐司，不要小黃瓜，蛋要全熟。」阿姨照做、做完遞給你。交代清楚，員工照做——你問得越清楚，它做得越對；講得含糊，它就亂猜。

生日派對員工 ＝ AI Agent

你只說：「這個月月底前，辦一場 20 人生日派對。」然後你去忙別的事。結果員工自己訂場地、買氣球、排菜單、發邀請、當天把派對辦起來——你只給目標，它自己做完整件事。

💬 感受一下差別

對一般 AI 說

「今天台北天氣如何？」→ 它回答你，結束。

對 AI Agent 說

「幫我整理這個資料夾裡所有檔案的清單。」→ 它說：「好的，我先把資料夾打開，逐個檔案看，再列成清單給您。」然後真的開始動手處理。

記住這句話：「AI 是你的員工，Agent 是會自己把工作做完的員工。」

⚠️ 常見陷阱

⚠️ 把 AI 當百科全書，只會查資料

打開 AI 就只問「XXX 是什麼？」——這樣它就跟 Google 差不多。正確心態：把它當員工下指令，「幫我做到這個結果」，而不是「告訴我這是什麼」。

⚠️ 以為 AI 一次就能做對

AI 不是神仙，就像新員工第一天上班一定有做不好的地方。做錯不要放棄，修正它：告訴它哪裡不對、你希望改成什麼。「會修正員工的老闆」，才是用好 AI 的關鍵。

✏️ 小測驗

1AI 和 AI Agent 最大的差別是什麼？

AI Agent 除了回答，還會自己動手把整件事做完。

2把 AI Agent 想成員工，什麼行為最像？

Agent 會自己規劃步驟、動手做、檢查結果，就像能幹的員工。

3「幫我做一個自我介紹網頁」這種指令，交給誰最適合？

這是一個「要動手做」的需求，正是 Agent 的強項。

📌 本節重點

AI Agent 是會幫你「動手做事」的工具，不是只會回答問題。接下來的課程，你要學的就是怎麼當一個好老闆，把工作交代給它。

第 1 章

安裝 OpenCode

主角登場：把 AI 員工帶進公司。像裝 LINE 一樣簡單——下載、安裝、開啟，三步完工。

⬇️ 三步安裝法

① 到官網下載 Desktop

前往官方網站的下载頁 opencode.ai/download；找不到就用 Google 搜尋「OpenCode desktop」，認明官網（opencode.ai）再下載，不要抓來路不明的安裝檔。

② 選對你的作業系統版本

Windows 選 Windows 版；Mac M 系列晶片請選 Apple Silicon 版。Mac 分 Intel 和 M 系列兩種，裝錯可能跑不動。

③ 雙擊安裝並開啟

下載完成後雙擊安裝檔，一路下一步，然後開啟。看到 OpenCode 視窗打開＝員工已經進公司了！（此時它還不會說話——還沒接上大腦，那是下一章的事。）

💡 不用再自己裝 Node 和 Git！

以前的路線

以前的電腦課會叫你先手動安裝 Node.js（地基）和 Git（時光機），裝完才能開始學 AI——光是打指令就勸退一半人。

AI Agent 時代

OpenCode Desktop 不需要它們就能直接安裝開啟；缺的工具，下一章直接叫 AI 自己裝給你看——你只要會「下載安裝」，其他交給它。

🖥️ 模擬：三步安裝

⚠️ 常見陷阱

⚠️ Mac 裝錯晶片版本

Mac 分 Intel 和 M 系列（Apple Silicon）兩種，裝錯可能跑不動或打不開。解法：M 系列一律選 Apple Silicon 版。

⚠️ 搜尋到山寨網站

廣告或仿冒網站可能排在搜尋前面，抓到非官方安裝檔有資安風險。解法：認明官網 opencode.ai，從站內 Download 頁下載。

⚠️ Windows 跳藍色警告「已保護你的電腦」

這是 SmartScreen 對新軟體的正常把關，不是壞掉。解法：點「更多資訊」→「仍要執行」（前提是確實從官網下載）。

⚠️ 以為要打一堆指令才裝得起來

那是 CLI 指令版的舊路線（先裝 Node 再 npm install）。初學者直接用桌面版，雙擊安裝就好，本課程不需要指令。

✏️ 小測驗

1初學者要安裝 OpenCode，正確做法是？

桌面版就像裝 LINE：官網下載 → 選對作業系統版本 → 安裝開啟。看到 OpenCode 視窗打開，員工就進公司了。

2為什麼現在不用先手動安裝 Node.js 和 Git？

OpenCode Desktop 本身不需要 Node/Git 就能安裝開啟；之後缺什麼工具，直接叫 AI Agent 自己偵測、自己安裝——這就是 AI Agent 時代。

3剛裝好的 OpenCode 視窗打開了，代表什麼？

視窗打開＝員工進公司。但 OpenCode 只是「駕駛座」，要等下一章接上大腦（模型），它才會回話做事。

📌 本節重點

三步安裝法：① 官網下載（opencode.ai/download，認明官網）→ ② 選對版本（Windows 版／Mac Apple Silicon）→ ③ 雙擊安裝開啟，像裝 LINE 一樣簡單。💡 不用再手動裝 Node.js 和 Git——缺的工具下一章叫 AI 自己裝。⚠️ 裝好≠能用：接上大腦是下一章的事。

第 2 章

接上大腦與環境建置

讓 AI 活起來、長出手腳：接上免費大腦（OpenCode Zen），再貼懶人包叫它自己把環境建好。

🔑 Step 1：申請 OpenCode Zen 免費金鑰

⏸ 授權點：這一步 AI 不能代辦

金鑰是你的私密資料，必須由你本人申請、親手貼給 OpenCode。

四個小動作拿到金鑰

① 開 opencode.ai/auth 用 Email 註冊登入
② 進管理後台（Console）找 API Keys 區塊
③ 點建立新金鑰（Create API Key）
④ 複製那串金鑰——只顯示一次，立刻貼到記事本存好！

💡 若後台要求先填付款資料才讓建金鑰：公務機或不想綁卡的同學先停下來問承辦。

🔌 Step 2：連接 OpenCode Zen（＋一定要重啟）

把大腦接上

Settings（設定）→ Providers（供應商） → 搜尋框打 zen 找到「OpenCode Zen」→ 點 Connect → 貼上金鑰 → 確認。

⚠️ 第 7 步不要跳過：完全關閉再重開！

新加的供應商常常要重啟才會出現在模型清單。白話：發完識別證要讓員工重新進門一次，證才生效。

⚠️ 清單裡長很像的「OpenCode Go」是付費訂閱制——本課程只走 OpenCode Zen。

📁 Step 3：專案與語系初始設定

新建專案，指定乾淨資料夾

先在電腦新增一個全新的空資料夾（例如：Open Code 0517），再讓 OpenCode 打開它工作——給員工一間「乾淨的辦公室」，他才不會弄亂你的檔案。

語言改繁體中文 ＋ 建立 Git 資料庫

進 Settings 把介面語言改成「繁體中文」，再點選「建立 Git 資料庫」（時光機）。若此時電腦還沒有 Git，等第五步 AI 裝完再補也來得及。

🧠 Step 4：選一顆免費的大腦

挑名字有 Free 的模型

打開模型清單（Models），挑名字有 Free 的，例如 DeepSeek V4 Flash Free（200K 上下文，講師實測好用）。換模型不用重做設定，隨時切換。

⚠️ 免費款會變動

官方說免費是「限時提供」，最準的查法是官方 Pricing 表：opencode.ai/docs/zen。名字僅供參考，當下以官網標 Free 的為準。

🔒 隱私守則

免費期間輸入的內容可能被拿來訓練模型。❌ 學生姓名、成績等個資絕不打進去；✅ 公開教材、自己寫的教案、假資料可以。真實學生資料先匿名化（學生A、學生B）。

✅ Step 5：第一次動手測試（三關驗證，不要跳過）

「會回話」不代表通了

有些免費模型很會聊天但不會用工具做事。真正有用的驗證是叫它建一個檔案——把這段貼給 AI：

請在目前這個資料夾建立一個檔案叫 test.txt，
內容寫一行：OpenCode 連線成功。
建立完成後，把這個檔案的內容讀出來給我看。

三關都要過才算通過

① 會回話：正常中文回應，不是錯誤訊息｜② 會動手：看得到它呼叫工具寫檔（跳出詢問按允許）｜③ 檔案真的在：打開資料夾 test.txt 存在且內容正確。只有①沒有②③ → 換另一顆 Free 模型重測。測完刪掉 test.txt。

🧰 Step 6：貼懶人包，叫 AI 自己蓋地基（#00 必裝）

先認識：終端機（PowerShell）

終端機就是電腦裡「打指令」的地方。待會 AI 安裝環境時你會看到它在終端機跑指令——不用會打，看得懂它在做事就好。（Windows 開始功能表搜尋 PowerShell 可以打開來看看。）

PS C:\Users\你的名字> _

把這段「魔法咒語」整段貼給 AI

這是 OpenCode 懶人包全集
https://github.com/mathruffian-dot/opencode-lazy-packs
請讀取 repo 內容，列出所有可用的懶人包，問我要裝哪些。

AI 會自己讀清單、列出 11 包問你要裝哪些 → 回答：「裝 00 環境建置」。

接下來 AI 全自動：偵測 → 安裝 → 驗證 → 回報

它會先偵測你電腦已裝什麼（缺的才裝），安裝 Git（時光機）、GitHub CLI（gh）、Node.js（地基）、uv（工具箱），每項驗證版本，最後回報一張結果表。

🖐️ 過程中需要你做的兩件事

① 跳出「要允許此應用程式變更你的裝置嗎？」（UAC 彈窗）→ 按「是」，AI 不能替你按，它會等你。
② AI 說「請重開終端機」→ 照做（剛裝好的工具舊視窗看不到）。
最後補一句：「幫我設定 Git 的使用者名字與 Email」——第 7 章上傳部署才不會卡住。

🎁 Step 7（選配）：#02 內部工具包——長出更厲害的手腳

🅰 文件處理（今天就用得到）

Word／Excel／PPT／PDF／圖片／QR Code 十件套。裝完直接說：「讀這份名單 Excel，套進獎狀模板每人產一份」「把這些 PDF 合併」「這 5 個連結各生一張 QR Code」。

🅱 影音工具（可跳過，剪影片課才用）

yt-dlp 下載影片字幕當逐字稿、FFmpeg 轉檔。時間不夠回家補，不影響 A 和 C。

🅲 語音 Edge-TTS（30 秒聽到聲音的 Wow 時刻）

讓 AI 用台灣中文開口唸結論給你聽，免金鑰免付費。裝完對它說：「把剛剛的結論用語音唸給我聽」。⏱ 三段互相獨立，課堂時間不夠先裝 A+C。

🖥️ 模擬：完整流程

⚠️ 常見陷阱

⚠️ 打字完全沒反應，或出現 No providers configured

裝好了但還沒接上模型——不是裝壞了。解法：照 Step 1、2 申請金鑰並連接 OpenCode Zen，重啟後再試。

⚠️ 連接完清單還是沒東西（或改了 MCP 沒生效）

沒有「完全關閉」就重開，新設定沒被載入。解法：工作管理員找到 OpenCode 按「結束工作」，再重新開啟。

⚠️ 選到 OpenCode Go 或付費模型，突然要收費

Go 是付費訂閱制，跟 Zen 長很像；免費也是「限時提供」。解法：認明 OpenCode Zen、挑名字有 Free 的；突然要錢＝免費期到了，回官方 Pricing 表換一顆。

⚠️ 金鑰貼錯，出現 Unauthorized / invalid api key

貼到一半、前後多空白、被自動換行切斷。解法：先貼到記事本確認整串在同一行，重新複製再連接。不小心外洩＝提款卡掉了：回 Console 立刻刪除重建。

⚠️ 學校網路連不上、一直轉圈

校園網路可能擋掉 AI 服務。解法：用手機熱點測一次——能通就是校網問題，請資訊組放行 opencode.ai 與 auth.opencode.ai。

⚠️ AI 卡住不動，好像當機

多半在等你：UAC 授權彈窗沒人按「是」，或它請你重開終端機你還沒做。解法：看螢幕有沒有彈窗；它說什麼就配合做什麼。

⚠️ AI 會聊天，但不會建檔案

這顆模型的「工具呼叫」能力不足。解法：換另一顆 Free 模型，重跑步驟五的三關驗證。同一任務失敗兩次以上，先換模型再懷疑自己。

✏️ 小測驗

1OpenCode 裝好了，但打字進去完全沒反應，最可能是？

OpenCode 只是「駕駛座」本身不會思考。裝好≠能用，必須先接上大腦：申請 Zen 金鑰 → Settings → Providers → 連接。

2供應商清單同時看到 OpenCode Zen 和 OpenCode Go，要選哪個？

兩個名字很像但完全不同：本課程只走免費的 OpenCode Zen；Go 是付費訂閱制方案，不要選錯。

3連接供應商之後，要做什麼新的大腦才會出現在清單？

新加的供應商常常要重啟才載入：務必「完全關閉」（可用工作管理員結束工作）再重新開啟。

4怎麼確認 AI 真的能「動手做事」，而不只是會聊天？

三關驗證：①會回話 ②看得到它呼叫工具寫檔 ③test.txt 檔案真的存在。只有回話不動手＝這顆模型不會用工具，換一顆 Free 模型重測。

5懶人包「#00 環境建置」會幫你自動安裝哪些工具？

#00 會先偵測缺什麼才裝：Git（時光機）、GitHub CLI、Node.js（地基）、uv（工具箱），每項驗證版本最後回報結果表。

6使用免費模型時，哪種資料可以放心丟給它？

免費期間輸入內容可能被用來訓練模型。學生姓名、學號、成績等個資絕對不打進去；需要處理真實學生資料時先匿名化（學生A、學生B）。

📌 本節重點

OpenCode 只是駕駛座，接上模型才會思考。流程背起來：① opencode.ai/auth 申請 Zen 金鑰（只顯示一次！）→ ② Settings → Providers → OpenCode Zen → Connect → 貼上 → ⚠️ 完全關閉重啟 → ③ 專案設定（乾淨資料夾＋繁體中文＋Git 資料庫）→ ④ 選 Free 模型（免費期會變，以官方 Pricing 表為準）。⑤ 三關驗證：會回話、會動手、檔案真的在。⑥ 貼懶人包咒語 → #00 讓 AI 自己裝環境（Git/GitHub CLI/Node.js/uv）；UAC 彈窗自己按「是」。⑦ #02 工具包選配：A 文件處理、B 影音（可跳過）、C 語音。🔒 隱私守則：免費模型可能拿輸入內容訓練，學生個資絕不打進去。

🎬 劇本對話模擬

💬 為什麼要一步一步確認

brainstorming = 開會確認需求

AI 是你的員工，你請它做專案就像請員工接大案子。專業員工不會一拿到案子就悶頭亂做，而是先開會反覆問你「要做給誰？要什麼功能？長什麼樣子？」，確保雙方想的是同一件事。

好的專案 = 清楚的需求 + 一步一步的確認

講得越清楚，AI 越不容易猜錯。AI 拿設計文件、計劃給你看時，花 10 秒讀一下，回一句「OK」或「這裡要改」——你越認真確認，後面越不會做錯方向白費工。

🧠 陷阱提醒

⚠️ 沒講清楚需求就喊「全自動」

只丟一句「幫我做一個點餐網站」就希望 AI 一次做對？這就像去餐廳只說「隨便」，廚師只能亂猜，端出來的往往不是你要的。需求不清楚沒關係，AI 會反問你，照實回答就好。

⚠️ 跳過確認一路喊「快點做」

AI 把文件拿給你看時，不理它或直接說「好好好快做」，就像開會時老闆不表示意見，最後交出來的東西跟你想的完全不一樣。

✏️ 課堂練習：看 AI 怎麼反問你

打一句話跟 AI 提出你的專案點子，例如：「我想做一個可以記錄運動的網頁。」（一句話就好，不用想得多完整。）

觀察重點

送出之後注意看：AI 是不是沒有馬上動手，而是開始反問你問題？把反問的問題記下來——問了幾個？問了什麼？

想一想

✏️ 小測驗

1專案一開始，AI 反問你問題的階段叫什麼？

brainstorming 就是「開會確認需求」：AI 先反問你細節，確保雙方想的是同一件事，才不會做錯方向。

2為什麼要讓 AI 寫設計文件和計劃？

設計文件和計劃就像員工的企劃書、時程表，白紙黑字讓你先確認再施工，確認過後才不會白做工。

3正確的專案流程順序是？

完整 SOP：提出專案 → brainstorming 提問 → 寫設計報告 → 寫實作計劃 → 執行 → 測試 → 上傳部署。

📌 本節重點

好的專案 = 清楚的需求 + 一步一步的確認。跟 AI 合作的完整 SOP 是：提出需求 → 反問釐清 → 寫設計文件 → 寫實作計劃 → 動手做＋測試 → 上傳部署。AI 不會不問就亂做，也不會做完就交差——你只要把需求講清楚、每步認真確認，它就是你最可靠的員工。

1「本機預覽」是什麼意思？

Git 就像「時光機」，每次改動都存一個備份點（Commit），改壞了可以回到之前的版本。所以要記得「留備份」，改壞了不可怕，可怕的是改壞了回不來。

⚠️ frontmatter 格式錯，AI 根本不載入

最常見的錯誤是「封面標籤」格式帶錯：少了最上面的 --- 或最下面的 ---、name/description 後面忘了冒號、冒號後面忘了空格（要寫 name: 早安問候，不是 name:早安問候）、內容沒貼在檔案最上面。判斷方法：喊了關鍵字 AI 只普通回應、沒照你寫的格式答，九成就是格式問題。回去對照範例一個字一個字檢查，改完存檔＋重開 opencode 再測。

⚠️ 觸發關鍵字設太普通，被誤觸發

關鍵字設「好」「嗨」「你」這種太常見的字，AI 幾乎每句話都會翻開這本書。要設「獨特一點」的字：「早安」「早安開始工作」。寫 SOP 內容時也一樣——一定會寫「遇到其他狀況以外來處理」，關鍵字越明確，誤觸發越少。

⚠️ 改完沒存檔／沒重啟就測試

每次改完 SKILL.md 都要存檔，重新打開 opencode 讓 AI 重新讀一次這本書，再喊關鍵字測試。

⏸ 兩個「授權點」：只有你能做

⚠️ GitHub 登入

第一次部署時，瀏覽器會跳出 GitHub 登入授權頁——必須你本人輸入帳號密碼完成登入。AI 不能也不該代替你輸入密碼。

⚠️ Google（Firebase）登入

部署到 Firebase 時也會跳出 Google 帳號授權——同樣必須你本人點擊同意。這兩個授權點是部署流程中 AI 會主動停下來等你的地方。

✏️ 小測驗

1GitHub 跟 Firebase 的分工是？

GitHub 是作品的「倉庫＋履歷」，負責管好版本的歷史；Firebase 是把作品「掛上網路的展示間」，負責上線給全世界看。兩者合作，作品才會被看到。

2哪個東西絕對不能上傳？

service account 金鑰（檔名像 *-adminsdk-*.json）等同倉庫保險箱的鑰匙，誰拿到誰就能讀改你的資料，絕對不能上傳 GitHub。反過來說，前端網頁的 Firebase API key 出現是正常的，真正保護你的是安全規則。

3.gitignore 是做什麼的？

.gitignore 是 Git 的「黑名單」：把不想上傳的東西寫進去，Git 就會自動跳過它們，例如 .env、service account 金鑰、opencode-sk-*.json、node_modules。

📌 本節重點

GitHub 管版本、Firebase 管上線，合作讓你的作品被全世界看到。上傳部署 5 大步：建 repo（gh repo create）→ commit+push → 啟用 GitHub Pages → firebase deploy --only hosting → 拿到網址分享，而你只要說「上傳部署」，AI 就會自動跑完整個流程，你只需要在 GitHub / Google 兩個「授權點」配合登入。

安全第一：service account 金鑰、opencode-sk-*.json 等機密檔案絕對不能上傳 GitHub，靠 .gitignore 這份「黑名單」自動擋住。之後每一次修改，AI 都會自動 commit+push（自動部署原則），你的作品永遠保持最新，每一版都有時光機紀錄可以倒回。

畢業了很興奮，想一口氣做出「很像大公司網站」的作品，結果做了兩天做不完、越做越亂。解法：先做「小」的——題目小、功能少、一個畫面搞定最好，先讓它「上線」最重要，做完之後隨時可以加功能。

📌 本節重點

這一章不教新工具，而是把第 0～7 章全部串起來：獨立完成一個「從零到有」的完整專案。結業檢查清單 8 大步，每一步都是你學過的能力；成功的關鍵不是「大」，而是「完成＋上線」。你已經會用 AI Agent 從零到有做出並公開一個作品——記住：AI Agent 是員工，你是老闆，學會下指令、會確認、會驗收，你就能做出任何你想要的作品。
