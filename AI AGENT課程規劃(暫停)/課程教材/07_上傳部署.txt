【說明】為什麼學這章
第 4 章你做了人生第一個「自我介紹網頁」，然後在自家客廳（本機
預覽）親眼看到它。但那時候我們說得很清楚：這個網頁「只有你的
電腦看得到」，別人打開瀏覽器是看不到的。

這一章，就是把你從「自家客廳」帶到「全世界」的那一步。

我們要用兩個工具，把作品送上網路給所有人看。請記住這兩個
很重要的比喻：

  GitHub  ＝ 作品的「倉庫 ＋ 履歷」
  你的作品不但有人幫你保管（倉庫），還記錄著你一路改版的歷史，
  證明你是「真的會做作品的人」——這份紀錄以後找工作、接案子
  都是你的門面（履歷）。

  Firebase ＝ 把作品「掛上網路的展示間」
  作品擺進展示間、掛上櫥窗，全世界的人路過都看得到。
  它給你的成品一個公開網址：https://你的專案.web.app

一句話記住這一章：GitHub 負責「管好作品的版本」，
Firebase 負責「把作品放上網路」，兩個合作，你的作品就
能被全世界看到。

═══════════════════════════════
【操作步驟】
═══════════════════════════════

整個流程分 5 步。別緊張，每一句指令你都不用背——
因為你說出「上傳部署」四個字，AI 就會幫你跑完大部分。
你只需要看懂「它在做什麼」，然後在幾個「要你授權」的
地方配合操作就好。

─────────────────────────────
第 1 步：建立 GitHub 倉庫（gh repo create）
─────────────────────────────
首先 AI 要幫你在 GitHub 上開一間「倉庫」（英文叫 repo），
把作品放進去。它用「遙控器」（GitHub CLI，英文簡稱 gh）
來做這件事，不用你開網頁手動操作。

─────────────────────────────
你：上傳部署。

AI：好，我來把作品送上網路！第一步，先在 GitHub 建立倉庫。
    請稍等⋯⋯
    執行 gh repo create 我的自我介紹 --public --source=. --remote=origin
─────────────────────────────

⏸ 暫停一下：會需要登入授權
如果這是第一次使用，會跳出一個「授權點」：螢幕會提示你登入
GitHub 帳號，甚至自動打開瀏覽器請你登入。

─────────────────────────────
AI：⚠️ 第一次使用，我需要你授權 gh 連到你的 GitHub 帳號。
    請在跳出的瀏覽器視窗登入 GitHub，登入完成後回到這裡。
    我會用 gh auth login 請你完成，再用 gh auth status 確認登入成功。
─────────────────────────────

你只要照著網頁上的指示點「授權 / Authorize」就好，就像手機
App 第一次登入要你按「同意」一樣。完成後，AI 會自己確認登入
成功，才繼續下一步。

─────────────────────────────
第 2 步：把作品存進倉庫（git commit + push）
─────────────────────────────
倉庫開好了，接下來要把你電腦裡的檔案「搬進」倉庫。這裡用到
的是第 1 章就裝好的 Git——那台「時光機 ＋ 檔案保險箱」。

過程是兩段式：
- git add / git commit：在「你電腦裡」先存一個「版本備份點」，
  就像拍照存檔。
- git push：把這個備份點「推」到 GitHub 的倉庫裡，就像把相簿
  上傳到雲端。

─────────────────────────────
AI：倉庫建立完成！現在把作品搬進去⋯⋯
    執行 git add .          （把全部檔案放進打包名單）
    執行 git commit -m "第一次上傳：我的自我介紹網頁"
                            （存一個版本備份點）
    執行 git push           （把備份點推到 GitHub）
    ✅ 完成！作品已經搬進倉庫了。
─────────────────────────────

（小知識：push 這個英文就是「推」的意思——把檔案從你的電腦
 一路「推」到雲端倉庫。）

─────────────────────────────
第 3 步：啟用 GitHub Pages（把作品變成網頁給人看）
─────────────────────────────
作品搬進倉庫之後，GitHub 還有一個很貼心的功能叫
「GitHub Pages」：它可以幫你把倉庫裡的作品「展示」成一個
公開網頁，讓任何人都能透過網址瀏覽。啟用方式也只要喊一聲，
AI 用「遙控器」下指令就完成：

─────────────────────────────
AI：接著我幫你啟用 GitHub Pages，讓作品直接變成一個公開網頁⋯⋯
    執行 gh api repos/你的帳號/我的自我介紹/pages -X POST
    ✅ 啟用完成！網址是：
    https://你的帳號.github.io/我的自我介紹/
─────────────────────────────

─────────────────────────────
第 4 步：Firebase 部署（把作品掛上網路的展示間）
─────────────────────────────
到這裡，作品在 GitHub 已經有網址了。但我們還要用 Firebase
這個「展示間」再上架一次，為什麼？因為 Firebase 的網址
（https://你的專案.web.app）更短、更快、更好記，也比較好
分享給一般人。這是「正式上架」的那一步。

首先要有一份說明書（firebase.json），告訴 Firebase「這個
網頁要放哪些檔案、上架到哪一個展示間」。這份說明書 AI 會幫你
建好，其中有一個很重要的欄位叫 site，是展示間的名字。

─────────────────────────────
AI：現在用 Firebase 正式上架。我先把設定檔 firebase.json
    建好，裡面指定展示間名稱：site: "自我介紹-sk"。
    然後執行 firebase deploy --only hosting
─────────────────────────────

⏸ 暫停一下：跟第 1 步一樣，第一次用 Firebase 也需要登入授權，
只是這次登的是 Google 帳號：

─────────────────────────────
AI：⚠️ Firebase 也是第一次使用，請在跳出的瀏覽器登入你的
    Google 帳號（firebase login）。
─────────────────────────────

一樣，按「授權」就好。登入完成，AI 就接著上架。

─────────────────────────────
第 5 步：拿到網址，分享給全世界
─────────────────────────────
上架完成，AI 會把所有的網址整理給你，通常是這樣一份清單：

─────────────────────────────
AI：✅ 上傳部署完成！
    GitHub 倉庫：https://github.com/你的帳號/我的自我介紹
    GitHub Pages：https://你的帳號.github.io/我的自我介紹/
    Firebase：https://自我介紹-sk.web.app
    我幫你把網址存到專案裡的「網址.txt」了，
    以後要分享隨時打開看。
─────────────────────────────

現在把手機拿出來，把 Firebase 那個網址貼給朋友——
他們就能看到你的自我介紹網頁了！恭喜，你的作品正式出道。

─────────────────────────────
之後每一次修改：自動部署原則
─────────────────────────────
從現在開始，請記住一個很重要的規矩（這個專案的作業守則
AGENTS.md 裡寫得很清楚，叫做「自動部署原則」）：

  每一次修改完程式碼，AI 都會自動執行 commit + push，
  不用再等你說「上傳部署」。

也就是說：你叫 AI 改個字、改個顏色、加一個功能——改完它
就會自己存版本、自己推到 GitHub。你的作品隨時保持最新，
而且每一版都有「時光機」紀錄，改壞了隨時倒得回去。

─────────────────────────────
完整對話流程示意（從你喊上傳部署到作品上線的劇本）
─────────────────────────────

你：上傳部署。

AI：好，我來把作品送上網路！先檢查一下專案，確認沒有
    機密檔案會被上傳⋯⋯確認完畢，開始囉！
    第一步，在 GitHub 建立倉庫⋯⋯

AI：⚠️ 第一次使用，請你在跳出的瀏覽器登入 GitHub 帳號，
    完成授權後跟我說一聲。

你：（在瀏覽器完成 GitHub 登入授權）好了。

AI：✅ 登入確認成功。gh repo create 完成！
    現在把作品搬進倉庫：git add → git commit → git push⋯⋯
    ✅ 搬好了。接著啟用 GitHub Pages⋯⋯
    ✅ 啟用完成！

AI：最後用 Firebase 上架。我建好 firebase.json，
    指定展示間名稱「自我介紹-sk」⋯⋯

你：（在瀏覽器完成 Google 登入授權）好了。

    https://你的帳號.github.io/我的自我介紹/
    https://自我介紹-sk.web.app
    網址也存進「網址.txt」了。

你：太棒了！我把網址貼給朋友看看。

AI：記得喔，之後每改一次，我都會自動幫你 commit + push，
    你的作品永遠是最新版本。

（看出來了嗎？你幾乎不用打任何技術指令——你只需要在兩個
  「授權點」登入帳號，剩下的搬檔案、上架、給網址，全部由
  AI 照著 SOP 完成。這就是「AI 是你的員工」最有成就感的一刻：
  你出嘴，它出手，作品就上線了。）

【常見陷阱】
═══════════════════════════════

陷阱 1：金鑰外洩（把「保險箱鑰匙」一起上傳了）
你的專案裡有一些檔案是「私密鑰匙」：最常見的是 Firebase 的
service account 金鑰（檔名長得像 xxx-adminsdk-xxx.json），
還有一份叫 opencode-sk-*.json 的服務帳戶金鑰。
這些檔案就像你倉庫的「保險箱鑰匙」——誰拿到它，誰就能讀、
能改你的資料，非常危險。所以它「絕對不能上傳到 GitHub」。
判斷方法很簡單：看到檔名裡有 key、secret、password、token、
adminsdk 這些字眼的檔案，就要先懷疑它是不是機密。
（反過來說：網頁程式裡的 Firebase API key（AIza⋯⋯）出現在
前端是「正常」的，不用緊張——真正保護你的，是 Firebase 的
安全規則，不是那串 key。）

陷阱 2：沒設 .gitignore（該藏的都藏不住）
你可能會想：「那機密檔案是不是別上傳就好？」問題是你哪記得
那麼多？所以 Git 有一個「黑名單」檔案叫 .gitignore——
你把它不想上傳的東西寫進去，Git 就會自動跳過它們，永遠不會
不小心上傳。這個檔案通常長這樣：

    .env
    *.local
    service-account.json
    opencode-sk-*.json
    node_modules

重點是：上傳之前先確認專案裡有 .gitignore、而且機密檔案
有被寫進去。放心，AI 在「上傳部署」的第一步就會自動檢查
這件「安全檢查」，發現可疑就會停下來問你——這就是為什麼
它會先暫停、不直接上傳。

陷阱 3：Firebase 展示間名字重複
每個 Firebase 的展示間（site）名字，在全世界都是「獨一無二」
的。如果你把展示間取名叫 "my-site"，別人早就用了，上架就會
失敗。而且規矩是：展示間名字要用「{英文縮寫}-sk」的格式
（例如 inventory-sk、gps-sk），每個新專案都要用「新的」名字，
不可以拿舊專案的名字重複使用。
如果上架時出現「名字衝突 / 已被使用」的錯誤，別慌——叫 AI
換一個名字（例如在縮寫後面加點數字）重新上架就好。真的不確定
哪個名字能用，AI 會先執行 firebase hosting:sites:list
檢查現有的名字，避免撞名。

═══════════════════════════════
【練習】動手做
═══════════════════════════════

目標：把你第 4 章做的「自我介紹網頁」，部署出一個可以
分享給全世界的公開網址。

步驟：
1. 打開 opencode，進到放著你自我介紹網頁的專案資料夾。
2. 對 AI 說：「上傳部署」。
3. 注意觀察它「上傳之前」會先做什麼——它有沒有先檢查機密
   檔案？有沒有先確認 .gitignore？
4. 遇到兩個「授權點」（GitHub 登入、Google 登入）時，配合
   在瀏覽器完成登入授權，再回來繼續。
5. 它跑完之後，會給你幾個網址。把「Firebase 的那個網址」
   （https://你的專案.web.app）記下來。
6. 拿手機或另一台電腦，打開那個網址——你應該能看到你的
   自我介紹網頁，而且不是 localhost！
7. 把網址傳給朋友或家人，問他們「看得到我的自我介紹嗎？」
8. 最後，故意叫 AI 改一行字（例如「加一句：我最喜歡的一句話」），
   然後觀察：它是不是「自動」幫你 commit + push 了，沒有等你
   再喊上傳部署？

完成後你就會發現：你沒有背任何技術指令，就靠「說一句話 +
按兩次授權」，讓自己的作品被全世界看到了。這就是 AI 課程
的「畢業成果」。

【本節重點】
═══════════════════════════════

1. 這章把「本機預覽」變成「公開上線」：從只有你自己看得到的
   localhost，變成 https://你的專案.web.app，全世界都看得到。
2. GitHub = 作品的「倉庫 ＋ 履歷」：管版本、留歷史，證明你
   真的會做作品。
3. Firebase = 「把作品掛上網路的展示間」：給你的成品一個
   好記、好分享的公開網址。
4. 上傳部署的 5 大步：建立 repo（gh repo create）→ git commit
   + push → 啟用 GitHub Pages → Firebase 部署（firebase deploy
   --only hosting）→ 拿到網址分享。而你說「上傳部署」，AI 會
   自動幫你跑完整個流程。
5. 兩個「授權點」需要你親手登入：GitHub 帳號、Google 帳號。
   這是保護你的帳號，不是麻煩。
6. 「自動部署原則」：修改完程式，AI 會自動 commit + push，
   你的作品永遠保持最新，而且每一版都有時光機紀錄可以倒回。
7. 安全第一：service account 金鑰、opencode-sk-*.json 等
   機密檔案絕對不能上傳 GitHub；靠 .gitignore 這份「黑名單」
   自動擋住它們。
8. 記住這句話：GitHub 管版本、Firebase 管上線，兩者合作，
   讓你的作品被全世界看到。
