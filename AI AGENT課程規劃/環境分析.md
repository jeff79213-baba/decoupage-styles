# 環境分析：這台電腦為了讓 AI Agent 順暢運行，裝了什麼？

> 這份文件是整個專案的「事實來源」。所有安裝步驟、課程內容都以此為準。
> 日期：2026-08-15

## 一句話總結
這台電腦裝了一串互相依賴的工具，像「蓋房子」：先打地基（Node.js），
再架鋼骨（Git），最後才有能力裝上 AI Agent（opencode）跟各種輔助工具。
每一樣都是為了讓 opencode 能「自動幫你做專案」而存在。

## 安裝順序圖

```
第一層　地基：Node.js ──┬──→ npm ──→ opencode ──→ superpowers / hallmark / deploy-workflow
                       └──→ npm ──→ Firebase CLI（把網頁搬上網）

第二層　鋼骨：Git ──→ GitHub CLI (gh) ──→ GitHub（把專案傳上網）

第三層　獨立生產線：Python ──→ .venv（文件處理套件）

備用工具箱：npm ──→ vercel / qrcode / @grinev/opencode-telegram-bot
```

**為什麼要照這個順序裝？**

因為後面的工具必須「站在」前面裝好的工具之上，少了前一層，後一層就完全跑不起來：

1. **先有 Node.js，才有 npm**：npm 是 Node.js 的一部分，沒裝 Node 就沒有「應用程式商店」。
2. **先有 npm，才有 opencode 和 Firebase CLI**：這兩個都是靠 `npm install` 裝的全域工具，商店沒開，什麼都裝不進來。
3. **先有 opencode，才談得上 skills**：superpowers、hallmark、deploy-workflow 這些「SOP 手冊」是給 opencode 用的，AI 助理本體都不存在，手冊給誰看？
4. **先有 Git，才有 GitHub CLI**：gh 只負責「遙控」，真正做版本控制、搬檔案的是 Git，沒裝 Git，gh 按下去沒有東西會動。
5. **Python 和 .venv 是一條獨立生產線**：它跟 Node 那條線互不相干，所以先後順序不影響；但 .venv 一定要在 Python 之後裝，因為它是「Python 工廠裡的隔離作業間」。
6. **備用工具箱最後裝**：vercel 等是額外加分的工具，不影響主流程，任何時候補裝都可以。

簡單說：**先有會跑東西的引擎（Node/Python），再有搬東西的運輸（npm），最後才有幫你做事的 AI（opencode）跟把成品送出去的大門（Git/GitHub/Firebase）。** 順序錯了，後面那層就「站不住」。
