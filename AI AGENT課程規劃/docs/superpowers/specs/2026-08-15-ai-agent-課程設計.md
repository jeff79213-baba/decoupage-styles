# AI Agent 課程專案設計文件

日期：2026-08-15
狀態：待審閱

## 專案目標

產出一套「AI Agent 教學專案」，包含兩個面向：

1. **給新 AI Agent 自動執行**：一台全新電腦安裝好 opencode 後，把「冷啟動手冊」丟給它，它能自動把環境建置到與目前開發機相同的狀態。
2. **給人學習的課程**：完全沒有程式基礎的一般人，透過教材學會認識 AI Agent、安裝、使用、建立 Skill、上傳部署。

### 畢業標準
學生能完整走完「裝好 → 用到 → 上傳」，最後產出一個能公開分享的網址。

## 目標學生
- 完全沒有程式基礎的一般人
- 熟悉日常電腦操作（會開瀏覽器、會安裝一般軟體）
- 教學以通用步驟為主，以開發機實際環境作為範例展示

## 三層結構

整個專案共用同一份「環境藍圖」，向下拆出兩份文件：

```
環境藍圖（事實來源）
    │
    ├── 給 Agent 的冷啟動手冊（指令式，可自動執行）
    └── 給人的課程教材（教學式，章節對應）
```

### 1. 環境藍圖（`環境分析.md`）

盤點開發機完整環境。每個工具記錄五個欄位：

| 欄位 | 內容 |
|------|------|
| 安裝了什麼 | 工具名稱與版本 |
| 用途 | 在整個流程中扮演的角色 |
| 為什麼需要 | 缺少它會發生什麼 |
| 安裝後的反應/後果 | 裝完會發生什麼、影響了哪些下游工具 |
| 如何驗證 | 用什麼指令確認裝成功 |

**環境清單（以開發機實測為準）：**

| 工具 | 版本 | 角色 |
|------|------|------|
| Windows + PowerShell 5.1 | Win10/11 | 作業系統與終端 |
| Node.js | v26.1.0 | 執行環境，opencode 的基礎 |
| npm | 11.13.0 | Node 套件管理器，安裝 opencode 用 |
| opencode | 1.16.2 | AI Agent 主程式（npm 全域安裝） |
| Git | 2.54.0 | 版本控制，專案管理 |
| GitHub CLI (gh) | 2.92.0 | 建立 repo、Push、啟用 Pages |
| Firebase CLI | 15.20.0 | 部署到 Firebase Hosting |
| Python | 3.12.10 | 文件處理（.venv 虛擬環境） |
| .venv | 10 套件 | python-docx、openpyxl 等文件工具 |
| superpowers skills | 14 個 | 專案工作流程（brainstorming 等） |
| 自訂 skill | 2 個 | hallmark、deploy-workflow |
| opencode 內建 skill | 1 個 | customize-opencode |
| npm 其他全域套件 | vercel、qrcode 等 | 補充工具 |

### 2. 給 Agent 的冷啟動手冊（`A_給Agent的冷啟動手冊.md`）

**定位**：純指令式文件，給新 AI Agent 依序執行。以通用安裝為主。

**每步格式（步驟卡）：**
```
## 第 N 步：<動作名稱>
🖥️ 執行：<指令>
✅ 預期結果：<安裝完成訊息>
🔍 驗證：<驗證指令 + 預期輸出>
⏸ 授權點：<有/無，需使用者操作>
⚠️ 若失敗：<替代方案>
💡 為什麼：<對下游的影響，一句話>
```

**設計原則：**
- 能自動的都自動；遇到授權（GitHub 登入、Firebase 登入）→ 停下來標示「需要使用者操作」
- 每步都驗證，不驗證不往下走
- 裝完後描述「行為模式」：確認 superpowers skills 已載入，AI 才會具備 brainstorming → plan → execute 的協作行為

**安裝順序（相依性驅動）：**
1. 檢查環境（OS、連網）
2. 安裝 Node.js（winget 或官方安裝檔）
3. 安裝 Git
4. 安裝 GitHub CLI（gh）→ ⏸ 登入授權
5. 全域安裝 opencode（npm install -g opencode-ai）
6. 安裝 Firebase CLI → ⏸ 登入授權
7. 安裝 Python + .venv
8. 安裝 superpowers skills
9. 複製個人化 skills（hallmark、deploy-workflow）與 AGENTS.md
10. 全環境驗證清單

### 3. 課程教材

**呈現**：HTML 教學網站（`學習清單.html`）＋ 章節 TXT 教材，沿用「考卷變教材」的既有風格與資料夾規範。

**首頁**：學習路徑圖、章節進度勾選（localStorage 記錄）、每章入口。

**章節結構（9 章）：**

| 章節 | 主題 | 學完能做 |
|------|------|----------|
| 0 | AI Agent 是什麼（AI 是你的員工） | 理解概念 |
| 1 | 準備工作：安裝 Node 與 Git | 裝好基礎工具 |
| 2 | 安裝 opencode 並設定 | 開啟第一個對話 |
| 3 | AI 怎麼跟我合作做一個專案（brainstorming→設計→計劃→執行→測試→部署） | 看懂完整工作流程 |
| 4 | 第一次合作：讓 AI 做一個小網頁 | 本機看到成品 |
| 5 | 認識 Skill（用 hallmark/deploy-workflow 當真實案例） | 看懂 skill |
| 6 | 動手做自己的第一個 Skill | 建立 skill |
| 7 | 上傳部署（GitHub + Firebase） | 產生公開網址 |
| 8 | 結業專案：完整走一遍 | 獨立完成 |

**每章 TXT 教材格式**（沿用考卷變教材規範）：
```
═══════════════════════════════
  章節名稱
  章節說明
═══════════════════════════════

【說明】為什麼學這章
【操作步驟】含「你與 AI 的對話框示意」
【常見陷阱】初學者容易卡住的地方
【練習】動手做
【本節重點】學到了什麼
```

**第 5 章「認識 Skill」教材重點**（用真實案例）：
- deploy-workflow：喊「上傳部署」→ AI 自動跑 GitHub + Pages + Firebase 流程
- hallmark：喊「需要設計感」→ AI 載入設計規範
- Skill = 給 AI 的「SOP 說明書」，關鍵字觸發自動套用
- 全環境共有 17 個 skill（superpowers 14 + 自訂 2 + 內建 1）

**第 3 章「專案工作流程」教材重點**：
- 完整 SOP：提出專案 → brainstorming 提問 → 寫設計報告 → 寫實作計劃 → 執行 → 測試 → 上傳部署
- 比喻：AI 是員工，brainstorming 是開會確認需求

## 測試策略
- 冷啟動手冊：無法在開發機完整重跑（會覆蓋現有環境），改用「逐指令驗證」方式：抽樣檢查每個指令的語法與預期輸出是否符合實際環境
- HTML 首頁：本機預覽確認路徑圖、進度勾選運作正常
- 課程教材：文字檔不需自動化測試，靠人審閱
